# Demo deployment on Render's free tier

A checklist for putting a **demo** of LevelUp DSA on Render's free plan (512 MB RAM, 0.1 CPU, no persistent disk, SMTP
blocked, free Postgres). It is a demo, not production: it sleeps when idle, forgets uploaded files, and some features
are switched off to fit in memory. Render's plans and limits change, so check Render's pricing page for the current
free-tier terms (in particular how long a free database lives) before you rely on it.

## What is different on the demo (read this first)

| Area | On the demo | Why |
|---|---|---|
| Memory | Torch and the embedding model are **never loaded** (`SEMANTIC_PATH_FIT=false`, `WARMUP_ON_START=false`) | Importing them alone is about 400-550 MB; the free plan has 512 MB |
| Resume upload | Everything works (skills, ATS score, feedback, salary, job matches) **except that career-path ranking is less precise**: it uses the survey signal only and skips the search over the knowledge base | That search needs the embedding model |
| Roadmaps | Work as normal in the default `ROADMAP_MODE=cached` (reviewed base roadmap + one short LLM call). `ROADMAP_MODE=full` would need the embedding model: do not use it here | |
| Forgot password | The page says plainly that reset by email is **not available**; no link is sent | Render blocks SMTP ports on the free plan. An administrator resets a password by hand |
| Uploaded resumes | Disappear on every deploy, restart and sleep. The analysis already saved stays; the ATS score and regenerated feedback for an old upload come back empty | No persistent disk |
| Idle | The service sleeps after a while with no traffic; the first request afterwards is slow (it starts the app again) | Free plan behaviour |
| Background jobs and rate limits | Kept in memory: a restart loses running roadmap jobs and resets limits | One worker, no shared store |
| Code questions | Run through OneCompiler (needs `ONECOMPILER_API_KEY`). Without a key, or if it is unreachable, the page gets a "runner unavailable" (503) answer and the rest of the app is unaffected | Piston is not used by the app |

Memory, measured on a Windows laptop (Linux on Render will differ somewhat; the real figure is on Render's Metrics tab, step 6):

| Moment | Before this change | With the demo settings |
|---|---|---|
| Server started (`create_app`) | 533 MB | **131 MB** |
| + first roadmap or resume request (search index and chunk list) | about 580 MB | **151 MB** |
| + first resume upload (spaCy English model) | about 660 MB | **230 MB** |

These are the Python process alone; gunicorn, database connections, PDF parsing and the LLM calls add to them. The expectation
is that it fits in 512 MB, but that is an expectation until you have seen the Metrics graph.

## Before you start

- The repository is on GitHub and Render can read it (Render dashboard > Account > connect GitHub).
- You have the same API keys you use locally (LLM, YouTube, Adzuna/Jooble, OneCompiler). Do not paste them anywhere but Render's dashboard.
- Your laptop has the project working, with PostgreSQL holding the real `survey_respondents` and `job_listings` data.
- The spaCy model is installed locally (needed by the seeding command): `python -m spacy download en_core_web_sm`.

## Steps

### 1. Export the seed data (on your laptop)

The two data tables are not in git. From the project folder, with your venv active and your local database running:

```powershell
$env:PYTHONPATH = "."; python scripts/export_seed_data.py
```

This writes `data/seed/survey_respondents.jsonl.gz` and `data/seed/job_listings.jsonl.gz` (git-ignored: the Stack Overflow
survey data is ODbL licensed, so do not commit or publish them). Expect 2,547 survey rows and 835 job rows.

### 2. Create the service and database from the Blueprint

1. Push this branch to GitHub (`deploy-render`), or merge it first if you prefer to deploy from `main`.
2. Render dashboard > **New** > **Blueprint** > pick the repository and branch. Render reads `render.yaml`.
3. It will create a web service `levelup-dsa-demo` and a database `levelup-db`, both on the **free** plan, and ask for the
   values of the variables marked `sync: false`.

### 3. Fill in the environment variables

| Variable | Value |
|---|---|
| `FLASK_ENV` | `production` (already set by the Blueprint) |
| `SECRET_KEY` | generated by Render |
| `DATABASE_URL` | wired to the database by the Blueprint |
| `WARMUP_ON_START` | `false` |
| `SEMANTIC_PATH_FIT` | `false` |
| `TRUST_PROXY_HEADERS` | `true` |
| `ROADMAP_MODE` | `cached` |
| `APP_BASE_URL` | the service's public address, e.g. `https://levelup-dsa-demo.onrender.com` (no trailing slash) |
| `LLM_PROVIDER`, `LLM_BASE_URL`, `ROADMAP_MODEL_ID`, `FAST_MODEL_ID`, `FALLBACK_MODEL_ID`, `LLM_MAX_RPM` | the same values as your local `.env` |
| `GEMINI_API_KEY`, `NVIDIA_API_KEY`, `GROQ_API_KEY`, `LLM_API_KEY` | only the key your provider uses; leave the others empty |
| `ADZUNA_APP_ID`, `ADZUNA_APP_KEY`, `JOOBLE_API_KEY`, `YOUTUBE_API_KEY` | your keys, or empty to skip that feature |
| `CODE_RUNNER` | `onecompiler` |
| `ONECOMPILER_API_KEY` | your key (empty = code questions answer "runner unavailable") |
| `MAIL_SMTP_HOST`, `MAIL_SMTP_PORT`, `MAIL_USERNAME`, `MAIL_PASSWORD`, `MAIL_FROM` | **leave empty** (SMTP is blocked; this is what makes the forgot-password page say it is unavailable) |

If Render will not accept an empty value, put a single space or a placeholder in the field and, after the first deploy,
clear it in the service's **Environment** tab.

Do not set `LOGOUT_ON_RESTART`, `UPLOAD_FOLDER`, `FAISS_INDEX_PATH` or any `PISTON_*` variable.

### 4. First deploy

Let the Blueprint build (the first build downloads CPU torch and takes several minutes). The service should reach "Live" and
`/health` should answer. If the build runs out of memory or time, see Troubleshooting.

### 5. Load the data into the Render database (from your laptop)

1. In the Render dashboard open the database `levelup-db` > **Connections** and copy the **External Database URL**.
2. In a PowerShell window, point this window (only) at it, adding `?sslmode=require` at the end if it is not there. Use a fresh window; closing it forgets the value.

   ```powershell
   $env:DATABASE_URL = "PASTE-THE-EXTERNAL-URL-HERE?sslmode=require"
   ```

3. Check which database you are about to write to (this prints only the host, never the password). It must be a Render host, not `localhost`:

   ```powershell
   python -c "import os; from urllib.parse import urlparse; print(urlparse(os.environ['DATABASE_URL']).hostname)"
   ```

4. Create the tables and load the two seed files (it only fills tables that are empty and never deletes anything):

   ```powershell
   $env:PYTHONPATH = "."; python scripts/setup_dev.py
   ```

   Expected end of output: `survey_respondents: 2547 rows`, `job_listings: 835 rows` and `Ready`.
5. Close that PowerShell window.

Your local `.env` is only a fallback: a `DATABASE_URL` already set in the window wins over it.

### 6. Smoke test (use the live address)

- [ ] `/health` returns `{"status": "ok"}`.
- [ ] `/db-check` says "Database connection: OK".
- [ ] The home page loads and is styled.
- [ ] Sign up, log out, log in (the session cookie must stick: this checks HTTPS cookies and the proxy setting).
- [ ] Complete the quiz and the conversation; the dashboard shows results.
- [ ] Generate a roadmap (a base roadmap personalised by the LLM; it finishes in seconds to a minute).
- [ ] Complete a roadmap step check (verified progression).
- [ ] Upload a small PDF resume: skills found, ATS score, salary insights, and path ranking appear. Ranking is the less precise survey-only version.
- [ ] Open a scenario with a code question and run it (needs the OneCompiler key; otherwise expect "runner unavailable").
- [ ] "Forgot password" shows the "not available on this server" message, not "we sent a link".
- [ ] Render dashboard > the service > **Metrics**: memory stays under 512 MB through all of the above. **Write the peak down.** If it reaches the limit, Render restarts the service ("Out of memory" in the Events tab).
- [ ] Logs show no `Traceback` and no `email_failed` surprises (a forgot-password attempt makes none, because nothing is sent).

### 7. Resetting a user's password by hand

Since email reset is unavailable, an administrator sets a new password by running, from your laptop against the external
database URL (as in step 5), a small script that calls `User.set_password(...)` for that user. There is no such script yet; ask
for one if the demo needs it.

## Turn it off

- **Pause the demo:** Render dashboard > the service > **Settings** > **Suspend Web Service**. No traffic and no compute. The database stays until you delete it (and free databases have a limited life, see Render's current terms).
- **Remove everything:** delete the web service, then delete the database `levelup-db` (this destroys the loaded data; you can reload it from your exports), or delete the Blueprint from the dashboard.
- **Keys:** the API keys you entered live in the service's Environment tab and go with the service. If you shared the dashboard or suspect a leak, also rotate them at the providers.
- **Seed files:** `data/seed/*.jsonl.gz` stay on your laptop only. Never commit them.

## Troubleshooting

| Symptom | Likely cause and fix |
|---|---|
| Build fails while installing torch | Check that `PYTHON_VERSION` is 3.11.x or 3.12.x (CPU wheels exist for these) and that `requirements-render.txt` still lists `torch==2.14.0+cpu` with the `--extra-index-url` line |
| Service restarts, "Out of memory" in Events | Confirm `WARMUP_ON_START=false` and `SEMANTIC_PATH_FIT=false` are really set, and `ROADMAP_MODE` is not `full`. If memory still reaches 512 MB, the app needs a larger instance for the demo |
| "Refusing to start in production: SECRET_KEY..." | `SECRET_KEY` is missing or too short; let Render generate it |
| Logged out immediately after logging in | `TRUST_PROXY_HEADERS` not `true`, or the browser blocks the cookie because the page is `http://` instead of `https://` |
| Resume analysis finds no skills | The seed step did not run or hit the wrong database; repeat step 5 and read its output |
| `Can't load plugin: sqlalchemy.dialects:postgres` | Fixed in the code (`postgres://` is rewritten to `postgresql://`); make sure you deployed this branch |
| First page after a pause takes a long time | The free service was asleep; this is normal |
